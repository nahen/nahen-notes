title: 📝末尾再帰(Tail Recursion)
---
再帰処理をおこなう関数の返り値が、その関数のみである構造。再帰で起こしがちなエラーであるスタックオーバーフローを防ぐ。

プログラミング言語によっては、末尾再帰で書いたコードはコンパイル時に、`for`や`while`のようなループ処理と同じような形に最適化されるらしい。その結果、通常の再帰処理よりも処理速度が速くなる。

## 再帰はスタックオーバーフローを誘発する
たとえば、入力値`x`を`n`回足し合わせる関数`repeat-add`を作るとする。（「かけ算`x * n`で良くない？」という意見は無視する）

`repeat-add`をそのまま再帰構造で実装する。注目してほしいのは2点。関数内部で`repeat-add`が呼び出されていることと、返り値である`(+ x (repeat-add x (- n 1))`に`+`の演算子がついていることだ。

```racket
;; 演算子付きで返すコード（末尾再帰ではない）
(define (repeat-add x n)
  (if (zero? n)
      0
      (+ x (repeat-add x (- n 1)))))
```

ここで`(repeat-add 3 10)`を実行すると、30が返る。3を10回足し算した結果だ。

ただし、この実装は欠点がある。足す回数`n`が多すぎるとスタックオーバーフローを起こすのだ。この構造は再帰処理をするたびに、評価待ちの式がどんどん積み重なってしまう。そして評価待ちの式の数だけ、メモリをどんどん圧迫してしまう。

```
(repeat-add 1 100)
(+ 1 (repeat-add 1 99))
(+ (+ 1 (repeat-add 1 98)))
(+ (+ 1 (+ 1 (repeat-add 1 97))))
(+ (+ 1 (+ 1 (+ 1 (repeat-add 1 96)))))
…
```

## 末尾再帰はスタックオーバーフローを防ぐ
同じ`repeat-add`を、今度は末尾参照の構造で作りなおした。内部関数`local-add`を新しく作り、`repeat-add`からその関数を呼び出している。`local-add`の返り値が、`(local-add (- n 1) (+ x result))`と関数だけになっていることに注目しよう。

```racket
;; 末尾再帰のコード
(define (repeat-add x n)
  (define (local-add res n)
    (if (zero? n)
        res
        (local-add (+ x res) (- n 1))))
        
  (local-add 0 n))
```

この関数は以下のように順番に実行される。評価待ちの式が積み重ならないので、メモリを圧迫しない。

```
(repeat-add 1 100)
(local-add 0 100)
(local-add 1 99)
(local-add 2 98)
(local-add 3 97)
(local-add 4 96)
…
```
